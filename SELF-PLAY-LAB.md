# Chess Evolution — Self-Play & Training Lab (v1.9.1)

There are now two distinct ways to run AI-vs-AI games:

1. **Watch AI play AI** in the browser. This is for viewing a single match on the chessboard.
2. **Self-Play Training Lab** in the browser lobby or `npm run train`. This runs many games in parallel on the computer hosting the Node.js server, collects labeled positions, fits a new evaluation model, and saves it for later games.

The older `npm run selfplay` personality league remains available for comparing the four handcrafted personalities. It is not the training command.

## Requirements

- Node.js 22 or newer, below Node 27
- `npm install`
- No GPU is required; self-play and the current trainer run on CPU

## Browser Training Lab

Start the server locally:

```powershell
npm install
npm test
npm start
```

Open `http://localhost:3000`, then use **Self-Play Training Lab** in the lobby. Start with a small run to confirm your machine's speed, then scale up.

Recommended first substantial run:

- Games: 200
- Workers: 4 (the server caps this to the available CPU threads)
- Search depth: 2

The browser panel reports games completed, positions saved, captures, inheritance events, W/D/L results, model generation, validation loss and learned weights. Use **Stop** to stop between games; finished game records are retained and a new model is only promoted if enough labeled samples were collected.

The browser Training Lab runs on the machine where the Node.js server is running. Opening the site on a phone does not move the training workload to the phone; the server performs the training. The API is enabled by default for local development. On a production deployment it remains disabled until the owner configures a private `TRAINING_API_KEY`. The owner then enters that key in the Training Lab; the browser stores it only for the current tab session and sends it only with training start/stop requests. Never commit the secret to GitHub.

## Command-line training

The browser panel and terminal use the same manager:

```powershell
npm run train -- --games 200 --workers 4 --depth 2
```

Options:

```text
--games N       Games in this generation (default 200; maximum 10,000)
--workers N     Parallel Node workers (default up to 4; capped by CPU threads)
--depth N       Search depth per move (default 2; range 1..5)
--time-ms N     Per-move time budget (default 120 ms)
--max-plies N   Safety limit per game (default 120)
```

Small smoke test:

```powershell
npm run train -- --games 8 --workers 2 --depth 1 --max-plies 30
```

## What is actually learned?

Each training game pits two identical copies of the current Balanced agent against one another, with both sides using the same model snapshot. The workers save completed games and every pre-move position. Each position includes nine white-perspective feature values and is labeled with the final game result (White win = 1, draw = 0.5, Black win = 0).

After the games finish, a mini-batch logistic-regression trainer updates nine relative evaluation weights:

- Material
- Inherited movement powers
- Capability synergy
- Center control
- Pawn advancement
- Exposure
- Protection
- Fork threats
- King safety

The next generation loads the saved weights. This is a real parameter-fitting step, not merely saving self-play games. It is a **compact learned linear evaluation model**, not a deep neural network or reinforcement-learning policy/value network. It can change the engine's evaluation emphasis, but improvement in playing strength is not guaranteed. Check the validation-loss metric and, more importantly, compare generations in balanced matches against a fixed baseline before treating a generation as stronger.

Because games are generated by the current agent, data can be biased toward its existing play style. More diverse opponents, openings, search budgets and held-out match testing are sensible later improvements.

## Saved data

Each run creates a new folder under `data/training/`:

```text
data/training/
  current-model.json
  latest-summary.json
  generation-001/
    games.jsonl
    positions.jsonl
    model.json
    summary.json
  generation-002/
    ...
```

`current-model.json` is the model loaded by the browser AI. The generation folders retain the input data and output model for audit and comparison. These files are local to the server computer and are excluded from the source ZIP / Git by default so that large personal datasets are not accidentally bundled.

## Repetition and draw protection

The shared game rules now track the position key and the half-move clock, so browser games—including AI-vs-AI watch games—automatically end as draws on threefold repetition or 100 half-moves without a pawn move or capture. Checkmate and stalemate are checked first. The search also penalizes revisiting a position in its current line to discourage loops before the official draw condition is reached. Training games additionally have a maximum-ply safety limit so one unusual game cannot run forever.

## Legacy personality league (comparison only)

The original runner remains available for quick comparisons among four fixed, hand-authored profiles:

```powershell
npm run selfplay -- --games 100 --depth 1 --time-ms 80 --max-nodes 2500 --max-plies 120 --seed 12345
```

Use `--mode self --personality balanced` for one personality against itself, or `--watch` to print the first game's moves in the terminal. Personalities are `balanced`, `evolutionist`, `guardian` and `tactician`. These are handcrafted evaluation profiles, not independently trained agents. This legacy command writes under `data/self-play/` and does not update `current-model.json`.
